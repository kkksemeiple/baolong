## 一、项目概述

暴龙万事屋是一个面向校园的**委托互助平台**：用户发布委托任务（代取、代买、租赁、家教、搬运等），其他用户接取并完成，报酬用平台内虚拟货币「屋币（WB）」结算。

前端覆盖需求文档中的全部七个模块：

| 模块 | 说明 | 页面数 |
|---|---|---|
| UA 用户与账号 | 注册、登录、找回密码、实名认证、登录安全 | 3 |
| TK 任务全流程 | 大厅、详情、发布、接取、状态流转、结算 | 4 |
| MS 消息与通知 | 任务会话、通知中心 | 2 |
| FM 社区论坛 | 帖子列表、详情、发帖、回帖 | 3 |
| UC 个人中心 | 资料、我的任务、钱包、收藏、历史、设置 | 6 |
| AD 管理后台 | 看板、用户、内容审核与仲裁、任务、虚拟货币 | 5 |
| PF 平台能力 | 虚拟货币账户、资金流水、对账 | 融入上述页面 |

## 五、接口层设计

### 5.1 统一响应结构

后端所有接口返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

`code === 0` 表示成功。**axios 响应拦截器会自动拆包**，因此调用方拿到的直接就是 `data`：

```ts
// 定义
export function fetchTaskDetail(id: number) {
  return get<Task>(`/tasks/${id}`)   // 返回 Promise<Task>
}

// 使用
const task = await taskApi.fetchTaskDetail(1)   // 直接是 Task，不用 .data.data
```

### 5.2 请求拦截器做了三件事

| 顺序 | 动作 | 说明 |
|---|---|---|
| 1 | 注入凭证 | `Authorization: Bearer <token>`，token 从 `localStorage` 读 |
| 2 | 注入幂等键 | 写请求自动加 `Idempotency-Key`（UUID），防止用户连点造成重复提交 |
| 3 | 保留调用方显式传入的 key | 网络重试场景可传固定 key，保证同一业务只生效一次 |

### 5.3 响应拦截器

| 情况 | 处理 |
|---|---|
| `code !== 0` | 弹 `ElMessage.error(message)`，并抛出 `BizError(code, message)` |
| HTTP 401 | 清除本地凭证 → 跳转 `/login?redirect=当前路径` |
| 4xx / 5xx | 按状态码映射友好文案；后端若返回 message 则优先使用 |
| 超时 | 提示「请求超时，请稍后重试」 |

### 5.4 文件上传

```ts
uploadImage(file, 'cert')   // scene: task | delivery | cert | post
```

`Content-Type` 必须由浏览器自动生成（带 boundary），**不要手动设置**，否则后端解析 multipart 失败。

## 八、Mock 模式

### 8.1 原理

`request.ts` 在 `VITE_USE_MOCK=true` 时把 axios 的 adapter 换成自定义实现：

```
组件 → axios → mockAdapter → 内存数据 → 返回 { code, message, data }
```

请求不会发出网络，但**经过完整的拦截器链路**，所以凭证注入、拆包、错误提示的行为与真实环境一致。

### 8.2 有状态

Mock 数据是**带状态**的：接单后任务状态真的会变，发布任务真的会冻结屋币，确认完成后余额真的会增加。刷新页面才重置。

### 8.3 覆盖范围

- 75 个路由全部实现，未实现的接口会返回 `Mock 未实现的接口：GET /xxx`
- 内置 8 条任务、3 个用户、2 个会话、5 条通知、3 篇帖子、6 条流水、待审/举报/争议数据各若干

### 8.4 关闭 Mock

```bash
# .env.development
VITE_USE_MOCK=false
```

生产环境（`.env.production`）默认已关闭。

## 九、状态管理

| Store | 状态 | 说明 |
|---|---|---|
| `user` | `token`、`user`、`loading` | 登录态；派生 `isLogin`、`isAdmin`、`isSadmin`、`creditScore`、`canTrade` |
| `app` | `unread`、`categories` | 导航栏未读角标、任务分类缓存 |

**设计要点**：

- 用户信息**先读 localStorage 缓存**再静默刷新，避免刷新页面时导航栏闪烁
- 未读数在登录后、进会话后、标记已读后更新
- 分类字典只拉一次，避免每次进大厅都请求

## 十一、与后端对接指南

### 11.1 启动顺序

```bash
# 后端（默认 8080）
mvn spring-boot:run

# 前端（5173，通过 vite proxy 转发 /api）
npm run dev
```

### 11.2 需要后端遵守的约定

| 约定 | 说明 |
|---|---|
| 响应结构 | 必须是 `{ code, message, data }`，`code === 0` 表示成功 |
| 鉴权 | 读取 `Authorization: Bearer <token>` |
| 幂等 | 读取 `Idempotency-Key` 请求头，同 key 重复请求返回首次结果 |
| 分页 | 列表用 `cursor` + `size`，返回 `{ list, nextCursor, hasMore }` |
| 管理端分页 | 用 `page` + `size`，返回 `{ list, total, page, size }` |
| 401 | 未登录/凭证失效时返回 HTTP 401，前端会跳登录页 |

### 11.3 字段对齐

前端类型定义在 `src/api/types.ts`，**以后端实际字段为准**。若后端字段不同，两种改法：

1. 改后端，对齐前端类型（推荐，类型定义即接口契约）
2. 在 `api/xxx.ts` 的返回处做一次字段映射

### 11.4 需要后端重点保证的三件事

1. **`/tasks/{id}/claim` 的并发安全**：同一任务只允许一人接取成功
2. **资金操作的原子性与幂等**：同一操作重复调用只生效一次，且不出现负余额
3. **接口级越权校验**：任何涉及资源归属的接口都要校验「这资源是不是你的」
