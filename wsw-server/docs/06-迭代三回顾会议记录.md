## 四、讨论出来的三个真问题

1. **状态词汇不一致**：迭代三的设计文档用 `WAITING / IN_PROGRESS / TO_CONFIRM`，而前端已交付的 56 个文件用 `OPEN / TAKEN / SUBMITTED`。
   - 讨论：改前端要动 6 个文件、50 处字面量，回归风险高；改后端等于推翻设计文档。
   - 结论：**内核沿用设计文档词汇，出参/入参在 `TaskWire` 翻译层转换**，并在文档里补一张对照表。

2. **评价数据无处存放**：信誉评分的「评价」因子在库里没有落点，导致「好评率」永远是先验值 90%。
   - 结论：`task_claim` 增加 `rating`、`review_content`，确认收货时写入。

3. **冻结金额与流水对不上**：原设计把「冻结」也记一条流水，出现金额为 0 的行，用户看不懂钱包。
   - 结论：**流水只记「可用余额」的有符号变动**，恒等式 `available − debt = SUM(流水.amount)`；`frozen` 由任务状态聚合镜像。
