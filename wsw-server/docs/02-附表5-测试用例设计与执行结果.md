# 附表 5 · 测试用例设计与执行结果分析

- 项目题目：暴龙万事屋 —— 校园任务大厅平台
- 迭代：迭代四
- 测试范围：后端 `wsw-server`（算法层 / 服务层 / 接口层）+ 前后端联调
- 测试环境：JDK 17.0.12、Spring Boot 3.2.5、MySQL 8.4.13、Node 20 + Vue 3 + Vite
- 编写：张皓宁；执行：全员
- 日期：2026-11-14

**测试策略**

采用「白盒打底、黑盒验收、联调补漏」的三层结构：

1. **白盒**：针对算法与状态机的纯函数写单元测试，不依赖数据库、不依赖当前时间，用固定时间戳断言，结果可复现。4 组 27 条，自动化执行（`mvn test`）。
2. **黑盒**：按学生真实使用路径设计功能用例，从 HTTP 接口进、从数据库与返回值出，不关心内部实现。12 个主要功能点。
3. **联调**：前后端真实对接后，按「发布 → 接单 → 交付 → 确认 → 结算」的主链路走查，发现的缺陷登记在第四节，并逐条回归。

## 四、测试执行结果分析

### 4.1 结论

- **白盒 27 条全部通过**；首轮 2 条失败均为用例自身缺陷，修正后通过，被测代码未改动，说明四个算法实现与设计文档公式一致。
- **黑盒 12 条**：9 条首轮通过，3 条（BT-09/BT-10/BT-12）首轮不通过，均定位到根因并修复后回归通过；BT-06 只做了 2 并发验证，200 并发压测留待后续。
- **联调阶段共发现并修复 24 个缺陷**（D-01~D-24），全部复测通过，无遗留阻断级问题。

### 4.2 缺陷的共性（为什么这轮 bug 这么多）

| 类别 | 数量 | 典型 | 根因 |
| --- | --- | --- | --- |
| 前后端契约不一致 | 10 | D-06、D-11、D-18、D-23 | 前后端并行开发，字段名/参数名靠口头约定；Spring 对多余参数静默忽略，错配表现为「200 + 无效果」 |
| 静默失败 | 6 | D-13、D-15、D-16、D-24 | 写库不看影响行数、统计口径漏算一类流水，错误被 try/catch 或默认返回值吞掉 |
| 状态机与并发 | 3 | D-14、D-21、D-22 | 原型期只考虑「正常路径」，异常路径（放弃、重复接单）没有配套记录 |
| 配置与环境 | 3 | D-01、D-05、D-09 | 框架默认值与项目约定冲突（1MB 上传、bean 重名、Mock 开关） |

**采取的对策**：① 新增 `contract_check.py` + `ApiContractTest`，把 9 组核心 VO 的字段做机器比对，纳入 `mvn test`；② 所有「状态机 → 数据库」写入统一判影响行数；③ 统计口径统一写进文档（哪些流水算发行、哪些算回收）；④ 前端请求统一走 `request.ts`，`Content-Type` 与 query/body 位置集中管理。
