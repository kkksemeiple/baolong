# 校园任务大厅 · 虚拟货币支付模块需求分析（精简版）

> TAPD 录入版｜每条需求 = TAPD 一条需求记录
> 字段对应：标题 / 父需求 / 描述（用户故事 + 验收要点）/ 优先级 / 故事点 / 迭代

---

## 一、模块定位

平台代收代付属「二次清算」需支付牌照，个人也无法申请微信/支付宝商户号。因此采用**平台内虚拟货币「校园币（CC）」**完成全部结算，并保留支付网关接口以备后续替换。

---

## 二、货币设计

| 项 | 值 |
|---|---|
| 名称 / 符号 | 校园币 / CC |
| 精度 | 整数，无小数 |
| 初始余额 | 注册赠送 100 CC |
| 持有上限 | 10000 CC |
| 获取 | 注册赠送、管理员发放、任务收入、（签到） |
| 消耗 | 发布任务冻结、违约金扣罚 |
| 账户模型 | 可用余额 `available` + 冻结余额 `frozen` + 欠款 `debt` |

**三条红线（写入用户协议）**

```
允许：完成任务获得 → 持有 → 发布任务消耗
禁止：充值 ✗  提现 ✗  用户间转账 ✗  兑换法币 ✗
```

**三条铁律**

1. 流水**只增不改**，修正靠「冲正」新增反向流水
2. 恒等式：`available + frozen − debt = SUM(流水)`
3. 每次变动必留痕：变动前后值、原因、关联任务、操作人

## 三、需求清单（20 条 / 65 点）

### MOD-01 账户体系

**R-01 校园币账户自动开通** ｜ P0 ｜ 2 点 ｜ S1
> 作为新用户，我希望注册后自动获得账户和 100 CC，以便直接发布任务。
> 验收：账户唯一（`uk(user_id)`）；赠送写流水；与注册同事务。

**R-02 余额与冻结余额查询** ｜ P0 ｜ 2 点 ｜ S1
> 作为用户，我希望看到可用、冻结、总资产，以便知道还能花多少。
> 验收：数值与库一致；冻结明细之和 = `frozen`；不可查他人。

**R-03 校园币流水明细查询** ｜ P0 ｜ 3 点 ｜ S1
> 作为用户，我希望查自己的收支流水，以便核对每一笔去向。
> 验收：时间倒序、游标分页；含变动后余额；**只读无删改入口**。

### MOD-02 校园币获取

**R-04 管理员单人发放** ｜ P0 ｜ 2 点 ｜ S1
> 作为管理员，我希望给指定用户发币，以便奖励或补偿。
> 验收：金额 1–500 且为整数；不超持有上限；写操作日志。

**R-05 管理员批量发放** ｜ P1 ｜ 3 点 ｜ S3
> 作为管理员，我希望按名单批量发币，以便一次完成班级奖励。
> 验收：异步 + 进度；单人失败不影响他人；同批次幂等。

**R-06 每日签到奖励** ｜ P2 ｜ 2 点 ｜ S3
> 作为用户，我希望每日签到领 5 CC，以便有持续使用动力。
> 验收：`uk(user_id, 日期)`；并发只成功一次；连续 7 天额外奖励。

**R-07 任务完成收入入账** ｜ P0 ｜ 3 点 ｜ S2
> 作为接单方，我希望任务完成即到账，以便及时看到收益。
> 验收：与任务状态同事务；失败则状态不推进；推送通知。

### MOD-03 消费与资金流转（**核心**）

**R-08 发布任务冻结校园币** ｜ P0 ｜ 5 点 ｜ S2
> 作为委托方，我希望发布时自动冻结校园币，以便接单方相信任务真会给报酬。
> 验收：原子扣减；余额不足拒绝；编辑报酬**增量冻结**；**200 并发不超扣**。

**R-09 取消/过期自动解冻** ｜ P0 ｜ 3 点 ｜ S2
> 作为委托方，我希望任务取消或过期后资金自动退回，以便不被无故占用。
> 验收：全额解冻；定时任务 5 分钟内触发；**重复触发只生效一次**。

**R-10 完成划转给接单方** ｜ P0 ｜ 5 点 ｜ S2
> 作为系统，我希望确认完成时把冻结资金转给接单方，以便交易闭环。
> 验收：同事务四步；双方流水零和；连点/超时并发只划转一次。

**R-11 违约金扣罚与欠款** ｜ P1 ｜ 3 点 ｜ S2
> 作为平台，我希望对爽约行为扣罚，以便约束行为并补偿受害方。
> 验收：扣罚顺序 available→欠款；欠款期禁止发布；补偿方有流水。

**R-17 交易幂等与防重复扣款** ｜ P0 ｜ 5 点 ｜ S2
> 作为系统，我希望资金操作重复请求只生效一次，以便杜绝重复扣款。
> 验收：三层防护（幂等键 / 状态机 / 唯一索引）；重复请求返回首次结果。

### MOD-04 争议与异常处置

**R-12 争议期间资金冻结** ｜ P0 ｜ 3 点 ｜ S3
> 作为用户，我希望发起争议后资金锁定，以便裁决前钱不被拿走。
> 验收：保持冻结并标记 `dispute_id`；争议中无取消/确认入口。

**R-13 仲裁裁决资金处置** ｜ P0 ｜ 5 点 ｜ S3
> 作为管理员，我希望按裁决结果处置资金，以便纠纷有明确了结。
> 验收：支持全额退回 / 全额划转 / 按比例拆分 / 证据不足退回；拆分金额零损耗；需填裁决理由。

**R-14 管理员异常冲正** ｜ P1 ｜ 3 点 ｜ S3
> 作为管理员，我希望错误发放能冲正，以便修正账目而不破坏流水。
> 验收：**禁止改删历史流水**，新增反向流水；二次确认 + 超管权限；单条流水只能冲正一次。

### MOD-05 对账与风控

**R-15 全平台总账对账** ｜ P0 ｜ 3 点 ｜ S3
> 作为管理员，我希望一键校验账目平衡，以便及时发现异常。
> 验收：三项校验（用户级 / 全局零和 / 冻结额匹配）空集为通过；只读不压线上；可导出。

**R-16 单用户余额对账** ｜ P1 ｜ 2 点 ｜ S3
> 作为管理员，我希望重算单个用户余额，以便处理账目投诉。
> 验收：输出差异与原因；修正须冲正留痕。

**R-18 异常交易监控告警** ｜ P2 ｜ 5 点 ｜ S3
> 作为管理员，我希望自动发现可疑交易，以便及时干预刷单。
> 验收：五条规则（高频互刷 / 秒完成 / 大额进出 / 同 IP 多账号 / 新号刷发）；1 分钟内告警；阈值可配。

### MOD-06 后台配置

**R-19 虚拟货币规则配置** ｜ P1 ｜ 3 点 ｜ S3
> 作为管理员，我希望在线调整货币参数，以便不发版就能调运营策略。
> 验收：改后立即生效；越界拒绝；变更历史可查；降上限不追溯。

**R-20 运营数据看板** ｜ P1 ｜ 3 点 ｜ S3

> 验收：恒等式成立（流通+冻结+欠款 = 发行−回收）；聚合走缓存；可导出。

## 四、关键业务规则（BR）

| 编号 | 规则 |
|---|---|
| BR-01 | 校园币为整数，任何金额不得出现小数 |
| BR-02 | 只有 `available` 可用于发布；`frozen` 仅能解冻或划转 |
| BR-03 | 扣减余额必须用原子 SQL + `affectedRows` 判断，禁止「先查再改」 |
| BR-04 | 所有资金操作集中在 `WalletService`，禁止跨模块直接改余额 |
| BR-05 | 资金变动与任务状态变更必须在**同一事务** |
| BR-06 | 解冻/划转以 `biz_type + biz_id + type` 唯一索引保证幂等 |
| BR-07 | 超时自动确认时长默认 72h，可配置 |
| BR-08 | 单人持有上限 10000 CC，超出部分不予发放 |
| BR-09 | 余额不足扣罚时记欠款，欠款期禁止发布任务 |
| BR-10 | 流水不可改删；冲正须新增反向流水且单条只能冲正一次 |

## 六、核心数据模型

```sql
-- 钱包账户
CREATE TABLE wallet (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id BIGINT NOT NULL,
  available INT NOT NULL DEFAULT 0,   -- 可用余额
  frozen    INT NOT NULL DEFAULT 0,   -- 冻结余额
  debt      INT NOT NULL DEFAULT 0,   -- 欠款
  version   INT NOT NULL DEFAULT 0,   -- 乐观锁
  UNIQUE KEY uk_user (user_id)
);

-- 不可变流水（只增不改）
CREATE TABLE wallet_transaction (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id BIGINT NOT NULL,
  type VARCHAR(32) NOT NULL,          -- ADMIN_GRANT / TASK_FREEZE / TASK_INCOME / ...
  amount INT NOT NULL,                -- 正入账，负出账
  balance_after INT NOT NULL,
  frozen_after  INT NOT NULL,
  biz_type VARCHAR(32), biz_id BIGINT,
  origin_tx_id BIGINT,                -- 冲正指向原流水
  idempotent_key VARCHAR(128),
  remark VARCHAR(255), operator_id BIGINT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_biz (biz_type, biz_id, type),   -- 幂等兜底
  UNIQUE KEY uk_idem (idempotent_key),
  UNIQUE KEY uk_origin (origin_tx_id),
  KEY idx_user_time (user_id, created_at)
);
```

**核心原子 SQL（R-08 冻结）**

```sql
UPDATE wallet SET available = available - #{amt}, frozen = frozen + #{amt}, version = version + 1
WHERE user_id = #{uid} AND available >= #{amt}
```

## 七、非功能需求

| 编号 | 要求 |
|---|---|
| NFR-01 | 任何情况下不出现负余额 |
| NFR-02 | 所有资金接口支持重复调用，效果等同一次 |
| NFR-03 | 200 并发抢同一账户余额不超发、不超扣（附压测报告） |
| NFR-04 | 余额查询 P95 < 200ms，流水分页 P95 < 500ms |
| NFR-05 | 每笔变动可定位到：谁、何时、为何、关联任务 |
| NFR-06 | 校园币不可充值、提现、转让、兑换法币 |
